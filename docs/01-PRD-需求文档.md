# AI 会议监听助手 — 产品需求文档（PRD）

- 版本：v0.1（草案）
- 日期：2026-08-26
- 状态：待评审
- 关联文档：[架构设计](./02-架构设计.md)

## 1. 产品定位

一个**全 AI 的会议监听与智能陪练系统**：

> 用户持续录音（模拟会议发言 / 销售陈述 / 汇报），多个拥有**独立人设、音色、目标、记忆与思维角度**的 AI 代理实时收听转写内容、持续思考并表态；在允许打断时，以语音 + 红色警报的形式插入交流；全程录音完整归档，会后 AI 可继续追问、用户继续作答，形成一次完整可回放的"AI 会议记录 + 智能助手"体验。

**首发场景**：销售陪练 —— 用户扮演销售，AI 扮演**客户**（默认，音色：高晴）与**老板**（音色：王新月）。架构上支持继续添加会计 / 财务 / 销售总监等任意角色。

## 2. 用户故事

1. 作为用户，我打开浏览器页面，点击开始，对着麦克风持续说话，左侧看到实时声波、开始时间和进行时长。
2. 我说到一半想回听刚才说了什么：拖动进度条，回放已拼接的音频，随时可以暂停录制再回听。
3. 我说话时，右侧实时出现转写文稿；我可以往上翻阅，也可以直接编辑修正错别字。
4. 客户（AI）在听我推销的过程中持续产生观点（不打断模式下静默显示观点卡片）；老板（AI）从管理视角默默评估我的表现。
5. 当我切到"可打断"模式，AI 觉得有必要插话时：屏幕弹出**红色警报框**，显示它想说的文字，同时用它的音色播放语音（播放可开关）。
6. AI 播放语音时我开口说话，AI 播放立即停止（barge-in），不打断我的节奏。
7. 我点击结束：录音自动保存到项目 `Record/` 子文件夹，文件名为 **日期 + Claude 会话 ID + 会话内容总结摘要**。
8. 结束后 AI 监听不停止：它基于全程内容向我提问，我用语音或文字继续回答，交流内容继续追加到同一次会议记录里。
9. 作为进阶用户，我可以直接在 Claude Code 里编辑每个角色的 CLAUDE.md、hooks、权限配置——角色即一个标准 Claude Code 项目。

## 3. 功能需求

### F1 录音工作台（左侧面板）

| 编号 | 需求 |
|---|---|
| F1.1 | 实时声波动画：反映当前麦克风音量的动态波形（说话时起伏，静默时平坦） |
| F1.2 | 显示开始时间（HH:MM）与进行时长（HH:MM:SS），实时刷新 |
| F1.3 | 录音控制：开始 / 暂停 / 恢复 / 结束 |
| F1.4 | 音频以 **5 秒分片** 录制上传；服务端与前端同步拼接为一条完整可回放音轨 |
| F1.5 | 进度条时间轴：已录时长为总长，可拖动定位回听任意位置；暂停录制状态下回听不影响后续续录 |
| F1.6 | 结束录音后音频无损保存（原始分片拼接，不二次压缩） |

### F2 实时转写（右侧面板）

| 编号 | 需求 |
|---|---|
| F2.1 | 本地模型实时转写（FunASR SenseVoiceSmall，离线），每分片完成后追加到文稿 |
| F2.2 | 文稿可翻阅（滚动历史）、**可编辑**（修正识别错误）；编辑结果作为会议纪要底稿，不回写音频 |
| F2.3 | 分片带时间戳，转写端到端延迟目标 < 3 秒 |
| F2.4 | **回声防护**：AI 播放语音的时段内，麦克风录入的 AI 声音不进入转写文稿与 AI 上下文 |
| F2.5 | 预留"翻译"开关（当前按同语言转写理解；后续可对转写结果叠加翻译行） |

### F3 多角色 AI 代理

| 编号 | 需求 |
|---|---|
| F3.1 | 角色属性：名称、人设提示词、目标、讲话风格、思维角度、音色、打断积极性（低/中/高）、启用开关 |
| F3.2 | 预置角色：**客户**（默认启用，音色=高晴）、**老板**（音色=王新月）；提供会计 / 财务 / 销售等角色模板 |
| F3.3 | 每个角色 = 一个独立的 Claude Code 实例：独立 session ID、独立 CLAUDE.md、独立 hooks、独立权限（allowedTools）、独立记忆体系 |
| F3.4 | 会议中可随时启用 / 停用某角色（停用即其 Claude 进程暂停接收增量） |
| F3.5 | 角色进程**懒启动**：仅会议开始且角色启用时才拉起对应 Claude CLI 进程 |

### F4 持续监听与持续反馈

| 编号 | 需求 |
|---|---|
| F4.1 | 总开关「AI 持续监听」：开启后，转写内容**每 5 秒 / 每 10 秒**（可选）增量推送给每个启用角色 |
| F4.2 | 每次推送附带该角色可配置的**提示词**（引导其关注点），并以**连续会话**形式发送（同一 Claude session，全程上下文累积） |
| F4.3 | 角色表态流：不打断模式下，角色产生的观点 / 态度 / 评分以**观点卡片**形式显示在右侧对应角色区域，不打扰录音 |
| F4.4 | **完整对话保留**：每次人机交互（增量输入 + AI 全部输出）逐条落盘，可审计、可回放 |

### F5 打断机制

| 编号 | 需求 |
|---|---|
| F5.1 | 模式选择：**不打断（默认）** / 可打断；会话中途可切换 |
| F5.2 | 可打断模式下，AI 决定插话时触发**红色警报**：醒目红色警示框 + 角色想说的话（文字） |
| F5.3 | 警报同时按角色音色 **TTS 播放**（独立开关：播语音 / 只显文字） |
| F5.4 | AI 插话期间**录音不停止**：用户声轨与 AI 语音在同一次会议记录中并存（AI 语音作为独立音轨/事件记录，回放时可区分） |
| F5.5 | Barge-in：AI 播放中检测到用户开口（新音频分片有能量且不在播放窗口内），立即 `streaming_cancel` 停止合成与播放 |
| F5.6 | 多角色同时想打断时的仲裁：按角色优先级（可配置，默认 老板 > 客户 > 其他）取一个，其余降级为观点卡片 |

### F6 结束与归档

| 编号 | 需求 |
|---|---|
| F6.1 | 点击结束后，录音自动保存到项目 `Record/` 子文件夹 |
| F6.2 | 命名规则：`日期_Claude会话ID_内容摘要`，如 `2026-08-26_1430_a1b2c3d4_客户异议处理演练.m4a`；摘要由 AI 在结束后自动生成并完成重命名 |
| F6.3 | 结束后「AI 监听」独立开关默认保持开启：AI 继续接收用户新的语音/文字输入，可继续提问，用户继续回答 |
| F6.4 | 会后交流全程（问答对）追加保存在同一会议目录（转写稿 + AI 对话日志），直至用户手动关闭会话 |
| F6.5 | 会话彻底关闭时：生成最终会议纪要（结构化：摘要、关键议题、角色观点汇总、待办/待答问题） |

### F7 浏览器交互与配置

| 编号 | 需求 |
|---|---|
| F7.1 | 浏览器打开页面即用（本机 `http://localhost:端口`），页面提供开始 / 结束等全部操作 |
| F7.2 | 配置页：角色管理（增删改、音色选择、提示词编辑）、发送周期、打断模式、TTS 播放开关、模型与网关参数 |
| F7.3 | 所有配置持久化，重启 Docker 后保留 |

### F8 Claude 端管理（双入口）

| 编号 | 需求 |
|---|---|
| F8.1 | 每个角色的项目文件（CLAUDE.md、`.claude/settings.json`、hooks、记忆）以标准 Claude Code 项目目录形式存在于仓库内，用户可直接用 Claude Code CLI / IDE 打开编辑 |
| F8.2 | 浏览器端修改提示词等参数时同步写回角色目录（单一数据源，避免两处配置漂移） |

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 内存 | **模块化加载**：待机（未开会）仅常驻 Web/编排服务（目标 < 300MB）；ASR 模型懒加载、空闲自动卸载；角色 Claude 进程按需起停 |
| 部署 | Docker Compose 一条命令启动；尽可能容器化（详见架构文档的宿主机例外说明） |
| 延迟 | 分片转写端到端 < 3s；打断决策到警报显示 < 1s；TTS 首包 < 2s |
| 可靠性 | 任一模块崩溃自动重启且不丢失已录音频；网络/网关故障时录音与转写本地继续，恢复后补发 |
| 安全 | API 密钥全部走 `.env` 注入，禁止硬编码；录音与会话数据仅存本地 |
| 隐私 | 转写用本地模型，音频不出本机；仅文本增量发送给对话模型网关 |

## 5. 角色规格（首发）

### 5.1 客户（默认角色）

- **音色**：高晴（CosyVoice 自定义音色）
- **目的**：扮演一个真实、有顾虑的潜在客户，检验用户的推销与应变能力
- **讲话风格**：口语化、随性，会突然提出常见异议（太贵了 / 再考虑 / 别家更便宜）
- **思维角度**：自身利益、信任感、风险规避
- **打断积极性**：高（客户随时会插话质疑）

### 5.2 老板

- **音色**：王新月（CosyVoice 自定义音色）
- **目的**：以管理层视角实时评估用户表现，关注结果、合规与风险
- **讲话风格**：直接、简短、犀利，复盘式提问
- **思维角度**：目标达成率、投入产出、组织风险
- **打断积极性**：中（点到即止，多在用户明显跑偏时打断）

### 5.3 扩展模板（V2）

会计 / 财务 / 销售总监 / 技术评审等，均按同一角色 Schema 定义，配置即加。

### 5.4 角色提示词模板框架

每个角色 CLAUDE.md 固定包含六段：`身份` / `目标` / `讲话风格` / `思维角度` / `行为边界（何时可打断）` / `输出协议（observe / interrupt / question 工具的调用规则）`。

## 6. AI 输出协议

角色通过**工具调用**表达行为（而非自由文本），保证可解析、可审计：

| 工具 | 含义 | 触发效果 |
|---|---|---|
| `observe` | 静默观点 / 态度 / 评分 | 右侧观点卡片，不打扰 |
| `interrupt` | 要求打断插话 | 红色警报 + 文字 + TTS（按模式与开关决定是否播） |
| `question` | 会后追问 | 会后交流阶段的提问（语音播报或文字） |

「不打断」模式下 `interrupt` 自动降级为 `observe` + UI 提示"该角色曾想打断"。

## 7. 边界（V1 明确不做）

1. **不做屏幕监控**：AI 监听的是录音转写文本，不是屏幕画面。
2. 不做多人说话人分离（单说话人假设；预留 speaker diarization 接口）。
3. 不做公网部署与多用户（单机单用户）。
4. V1 角色代理的"操作电脑"权限限定在挂载的共享工作区内（容器内文件读写），不控制宿主机 GUI。

## 8. 待确认问题（已给默认决策，可推翻）

| # | 问题 | 当前默认决策 |
|---|---|---|
| Q1 | "实时翻译"是指外语互译，还是同语言实时转写？ | 按**实时转写**实现，翻译作为后续开关 |
| Q2 | TTS 播放开关默认开还是关？ | 默认**开**（可打断模式下有声插话是核心体验） |
| Q3 | 会后交流是否有时间上限？ | 无硬上限，用户手动关闭会话 |
| Q4 | 多角色同时打断的仲裁规则？ | 按角色优先级，默认 老板 > 客户 |
| Q5 | 本地 ASR 跑在 Docker（CPU）还是宿主机（MPS 加速）？ | 默认 Docker 内（满足"尽可能 Docker"）；提供 host-worker 模式开关 |
| Q6 | AI 插话语音是否混入用户录音主音轨？ | 不混入；AI 语音作为独立事件/音轨保存，回放可区分 |
