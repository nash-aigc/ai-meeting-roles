## 1. 已验证的关键可行性（2026-08-26，本机实测）

| 依赖 | 结论 |
|---|---|
| Claude CLI `2.1.235` | 支持 `--input-format stream-json`（**实时流式输入**，即 VSCode 插件同款双向交互模式，非单次指令）、`--output-format stream-json`、`--include-partial-messages`（流式首字延迟）、`--session-id <uuid>`（指定会话）、`--resume`（续接会话）、`--settings`（独立配置）、`--mcp-config`（挂自定义工具）、`--allowedTools`（权限白名单） |
| cosyvoice-tts skill | 高晴 / 王新月自定义音色可用；`cosyvoice-v3-plus` 合成；`SpeechSynthesizer.streaming_cancel()` 可中断合成（barge-in 基础） |
| audio-transcriber skill | FunASR SenseVoiceSmall 本地离线转写（~897MB 模型，缓存后离线加载，约 17x 实时） |
| 对话模型 | 走 NewAPI 网关（本机 `:3000`），模型 `deepseek-v4-flash`；Claude CLI 通过 `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` 环境变量指向网关即可，无需改造 CLI |

**核心结论：全部核心链路零新技术风险，均为已在本机跑通的组件的组合。**

### 容器划分与加载策略（模块化、非全量）

| 容器 | profile | 启动时机 | 常驻内存预算 |
|---|---|---|---|
| gateway | core（默认） | docker compose up 即起 | ~150MB |
| agent-runner | core（默认） | 随 gateway 起；**Claude 进程按角色懒启动** | 管理器 ~80MB + 每启用角色 ~200MB |
| asr | `--profile asr` 或由 gateway 懒启动/停止 | 第一次会议开始 | 模型加载 ~1.8GB，空闲 10min 卸载回落 ~300MB |

**待机总占用目标 < 300MB**（未开会时：gateway + agent-runner 管理器，无 Claude 进程、无 ASR 模型）。

## 3. 关键设计决策

### 3.1 Claude 实时交互：stream-json 双向长驻进程（不是反复 `claude -p`）

每个启用角色一个**长驻** Claude CLI 子进程，会议全程不退出：

```bash
claude -p \
  --input-format stream-json \
  --output-format stream-json \
  --include-partial-messages \
  --session-id <角色会话UUID> \
  --model deepseek-v4-flash \
  --permission-mode acceptEdits \
  --allowedTools "Read Edit Write Glob Grep" \
  --mcp-config meeting-tools.json \
  --settings roles/boss/.claude/settings.json \
  --dangerously-skip-permissions 不使用；权限走白名单
```

- **发送增量**：编排器每 5/10 秒通过 stdin 写入一条 `{"type":"user","message":{"role":"user","content":[{"type":"text","text":"<增量转写+角色提示词>"}]}}`，进程保持存活——这就是"实时互动、连续对话"，与 VSCode 插件同机制。
- **接收行为**：stdout 持续读 JSONL：`assistant` 消息中的 `tool_use`（`interrupt`/`observe`/`question`）与文本增量实时解析；`--include-partial-messages` 让打断首字延迟可控。
- **进程崩溃恢复**：`--resume <sessionId>` 原地续接（Claude 服务端保存会话状态），业务无损。
- **会后继续交流**：录音结束后**同一进程继续存活**，用户的会后语音/文字照常走 stdin——天然满足"结束后 AI 继续问、用户继续答"。

### 3.2 对话模型走 NewAPI 网关

agent-runner 容器内为 Claude 进程注入：

```
ANTHROPIC_BASE_URL=http://host.docker.internal:3000   # 本机 NewAPI
ANTHROPIC_AUTH_TOKEN=<.env 注入，勿硬编码>
ANTHROPIC_MODEL=deepseek-v4-flash
# 备用线路（火山引擎中转）在网关层配置，应用侧无感
```

Claude CLI 原生支持 Anthropic 协议网关替换，NewAPI 提供 `/v1/messages` 兼容端点，无需任何代码改造。

### 3.3 每角色 = 一个标准 Claude Code 项目（满足"独立实例"需求）

```
Meeting/
├── roles/
│   ├── customer/                     # 角色：客户（默认）
│   │   ├── CLAUDE.md                 # 人设六段式（身份/目标/风格/思维/边界/输出协议）
│   │   ├── .claude/settings.json     # 独立 hooks、权限、参数
│   │   ├── .mcp.json                 # MeetingTools MCP 挂载
│   │   └── memory/                   # 独立记忆体系（跨会议累积）
│   └── boss/                         # 角色：老板（同构）
├── Record/                           # 会议录音归档（PRD F6.1）
│   └── 2026-08-26_1430_a1b2c3d4_客户异议处理演练.m4a
├── transcripts/                      # 每次对话全量 AI 日志
│   └── <meetingId>/customer.jsonl · boss.jsonl · meeting.md
├── db.sqlite                         # 会话/分片/事件元数据
├── docker-compose.yml
├── .env                              # 密钥（不进 git）
└── docs/
```

- agent-runner 以 `roles/<role>/` 为 cwd 启动 claude → CLAUDE.md / hooks / settings / 记忆**天然按目录隔离**，用户可随时用 Claude Code 打开该目录直接编辑（PRD F8.1）。
- 浏览器端改提示词 = 写回 `roles/<role>/CLAUDE.md`，单一数据源。

### 3.4 角色行为 = 工具调用（可解析、可仲裁）

本地 stdio MCP server（`meeting-tools`，<100 行）暴露三个工具：

| 工具 | 参数 | 编排器动作 |
|---|---|---|
| `observe` | `text, sentiment?` | 推观点卡片到右栏（不打扰） |
| `interrupt` | `text, urgency` | 「可打断」模式 → 红色警报 + TTS + 播放窗口登记；「不打断」模式 → 降级 observe + UI 角标 |
| `question` | `text` | 会后阶段播报提问 |

打断仲裁器：同窗多角色 `interrupt` → 按优先级取 1 个执行，其余降级。

### 3.5 ASR 管线（分片增量，防回声）

```
浏览器 MediaRecorder(5s, webm/opus) → WS → gateway
  → ffmpeg 转 16k mono wav（内存管道，不落临时文件）
  → asr 容器 SenseVoiceSmall 增量转写（返回该分片文本+时间戳）
  → gateway 过滤「播放窗口」分片（AI TTS 时段内 → 丢弃不进文稿/LLM）
  → 转写追加 UI + 定时增量发给角色 Claude 进程
```

- **懒加载**：模型仅在第一片到达时加载；**空闲卸载**：连续 10 分钟无分片 → 卸载模型释放 ~1.5GB。
- **host-worker 模式**：`.env` 开关切到宿主机 Python（MPS 加速，复用 audio-transcriber 环境）——性能优化备选，Docker 内 CPU 版为默认。

### 3.6 TTS 管线（打断 & barge-in）

- gateway 内直调 DashScope CosyVoice（云 API，无本地模型）：音色注册表 `customer→高晴`、`boss→王新月`，质量优先 `cosyvoice-v3-plus`，语速 1.2–1.5。
- **播放窗口登记**：合成开始/结束时间戳写入 `SegmentBuffer`，ASR 据此过滤回声（见 3.5）。
- **barge-in**：播放期间收到新分片且其能量高于阈值且时间窗在播放后 → `streaming_cancel()` 中断合成，播放立即停，录音继续。
- 播放开关（PRD F5.3）只影响是否出声，文字警报始终显示。

## 4. 数据模型（db.sqlite 核心表）

| 表 | 关键字段 |
|---|---|
| meetings | id, claude_session_ids(JSON per-role), started_at, ended_at, status, summary, audio_path |
| segments | meeting_id, idx, start_ts, end_ts, path, asr_text, is_playing_window |
| agent_events | meeting_id, role, type(observe/interrupt/question), text, urgency, created_at |
| transcripts | meeting_id, role, direction(user/assistant), payload(JSON), created_at ← **全量对话保留** |
| roles | name, voice, prompt_path, enabled, priority, interrupt_aggressiveness |

## 5. WebSocket 消息协议（浏览器 ↔ gateway）

| 方向 | 消息 | 说明 |
|---|---|---|
| ↑ | `audio.chunk` (binary) | 5s 分片（webm/opus） |
| ↑ | `meeting.start / pause / resume / stop` | 控制信令 |
| ↑ | `transcript.edit` | 用户手动修正文稿 |
| ↑ | `user.text` | 会后文字输入 |
| ↑ | `config.update` | 周期/模式/开关/角色配置 |
| ↓ | `transcript.delta` | 新转写文本（带时间戳） |
| ↓ | `agent.observe` | 角色观点卡片 |
| ↓ | `agent.interrupt` | 红色警报（text + role + urgency） |
| ↓ | `tts.start / tts.end` | 播放窗口（前端同步 ducking UI） |
| ↓ | `meeting.archived` | 归档完成（返回最终文件名+摘要） |
| ↓ | `asr.status` | 模型加载/卸载状态（UI 提示） |

## 6. 归档流程（PRD F6）

```
meeting.stop
  → 分片按序拼接为完整音轨（ffmpeg concat，无重编码）
  → 每角色 Claude 进程被要求输出「会话摘要」（≤20字）
  → 重命名 Record/<日期_HHmm>_<sessionId前8>_<摘要>.m4a
  → 写回 meetings 表 + 生成 meeting.md（纪要/观点汇总/待答问题）
  → 状态切 postTalk：进程保活，继续接收用户语音/文字 → 追加 transcripts
  → 用户点「关闭会话」→ 各角色进程退出，ASR 空闲计时开始
```

## 7. 安全

1. **密钥只进 `.env`**（见 `.env.example`），compose 注入，代码与文档零明文；`.env` 入 `.gitignore`。
2. 角色权限白名单（`--allowedTools`）最小化：V1 仅 `Read/Edit/Write/Glob/Grep` 且限定 `roles/<role>/` 工作区，防越权。
3. 录音、转写、日志仅本地存储；仅文本增量出网（对话网关 + TTS 云 API）。
4. 服务只绑定 `127.0.0.1`，不暴露公网。

## 9. 风险与备选

| 风险 | 概率 | 备选 |
|---|---|---|
| Docker 内 CPU 转写偏慢（>3s/分片） | 中 | host-worker 模式（宿主机 MPS）；或换 mlx-whisper |
| 网关（NewAPI）转发 Anthropic 协议兼容性 | 低 | 直连火山引擎中转线路（网关层切换，应用无感） |
| 长会话 Claude 上下文膨胀 | 中 | 编排器对超长转写做滚动摘要（UI 仍显全量，LLM 收摘要） |
| 多角色并发打断体验混乱 | 中 | 仲裁优先级 + 冷却时间（同角色 60s 内不重复打断） |

## 10. 开发工作流（前后端分离 + 热更新，2026-08-26 补充）

**目标**：前端排版/交互高频迭代时，**Docker 完全不动**，改动秒级生效。

### 10.1 模式

```
宿主机（M1 Max）                        Docker（仅后端）
─────────────────────                  ─────────────────────────────
cd web && npm run dev                  docker compose up -d
Vite dev server :5173                    ├─ gateway      :8787
  · 改 .vue/.ts → 浏览器 HMR <1s          │   (开发模式: 源码卷挂载
  · /api → 代理 → gateway:8787            │    + uvicorn --reload)
  · /ws → 代理 → gateway:8787 (ws)        ├─ agent-runner (按需)
                                          └─ asr          (懒启动)
```

- **前端改动零部署**：排版、组件、逻辑全部热更新，与 Docker 无关。
- **后端改动也热载**：开发 profile 下 Python 源码卷挂载 + `uvicorn --reload`。
- **前端独立 mock 模式**：`npm run dev` 后访问 `?mock=1`，不依赖任何后端即可演示全部 UI 状态（转写流、观点卡片、打断警报、会后交流），纯排版迭代期间连 Docker 都不用起。
- **生产**：`npm run build` 产出 `web/dist/`，由 gateway 静态托管（此时才涉及重新构建镜像，生产发布本就低频）。

### 10.2 为什么前端 dev server 必须在宿主机

macOS Docker Desktop 的卷挂载（virtiofs/gRPC-FUSE）**不传播 inotify 文件变更事件**，Vite 的 HMR 文件监听在容器内不可靠；且容器内编译再经 VM 边界推送 WebSocket 反而更慢。前端 HMR 宿主机直跑是唯一稳定方案，后端留在 Docker 满足"尽可能容器化"。

### 10.3 硬件适配（Mac M1 Max / 64GB）

| 项 | 调整 |
|---|---|
| 镜像架构 | 全部 ARM64 原生镜像（python:3.12-slim、torch arm64 wheel），禁用 x86 模拟 |
| ASR 空闲卸载 | 由 10min 放宽为 **30min 可配置**（64GB 下 SenseVoiceSmall 常驻 ~1.8GB 压力极小，卸载仅为整洁非必需） |
| 角色并发 | 每角色 Claude 进程 ~200MB，10 角色同开 ~2GB，无压力 |
| Docker Desktop | 建议分配 8-16GB / 6+ CPU（ASR 容器峰值） |
| 内存总预算 | 待机 <300MB 不变；会议中全开（双角色+ASR）~2.5GB，占 64GB 的 4% |

### 10.4 目录约定

```

├── web/          # 前端（Vite + Vue3 + TS + Tailwind v4，宿主机开发）
├── server/       # 后端（FastAPI gateway / agent-runner / asr，Docker 运行）
├── roles/        # 角色项目目录（Claude Code 实例）
```

## 11. ASR 方案变更（2026-08-26，用户决策）

**用户录音的实时识别引擎改为：火山引擎「豆包流式语音识别 2.0」（云端，Seed/BigAsr 协议）。**
原因：识别更精准、效率更好；时长版计费约 1 元/小时，成本可接受。

| 项 | 变更前 | 变更后 |
|---|---|---|
| 实时识别（用户录音） | 本地 FunASR SenseVoiceSmall（asr 容器） | **火山豆包流式 ASR**（wss://openspeech.bytedance.com，`volc.seedasr.sauc.duration` 时长版） |
| 本地 FunASR | 主引擎 | 降级为**会后整段重转写 / 离线兜底**（可选容器，非必选） |
| 音频链路 | 5s webm 分片 -> 后端转码 -> 本地模型 | 浏览器 PCM 采集（16k/16bit/单声道）-> **WebSocket 直连火山**（V1 dev）；gateway 就绪后迁服务端中转 |
| 密钥 | .env（服务端） | dev 期 localStorage（设置面板填写）；正式期迁 .env |

### 实现位置（web/）

- `services/volcAsr.ts`：火山流式 ASR 客户端（首帧 JSON 配置 + 二进制 PCM 帧 + 结束帧；utterances 分句 definite -> final，否则全量 text diff 兜底）
- `services/audio.ts`：新增 PCM 采集链（ScriptProcessor -> 16k 降采样 -> `pcmConsumer` 注入），暂停时 `AudioContext.suspend()` 冻结供给
- `services/speech.ts`：浏览器 Web Speech API 降级引擎（Chrome 系依赖 Google 服务，部分网络不可达）
- 设置面板「实时识别引擎」：引擎切换 + App ID / API Key / resource id / cluster 配置（localStorage，密钥不进代码库）
